# Вертушка — 2026-08-27

## Итог дня
День про цену: две прод-правки вокруг радара и истории цен, обе про одно и
то же — приложение показывало пользователю не ту цифру. Сначала «сейчас» в
шторке порога считалось по оценке Discogs вместо живой цены маркета, потом
выяснилось, что график цены вообще не видел половину своей истории из-за
денормализованного `record_id`. Плюс прогон MB/CAA-рефреша (+28K обложек) и
переписанный простым языком раздел README.

## Ключевые фиксы/решения

### Цена и радар
- **График цены не видел половину истории** — эндпоинт брал привязку
  снапшота к пластинке из денормализованного `listing_price_history.record_id`.
  Денорм пишется в `_upsert_listing` значением `matched_record_id` **на момент
  снятия снапшота**, а матчинг листингов — отдельная часовая задача, которая
  историю не досыпает: в `listing_matcher` нет ни одного обращения к
  `ListingPriceHistory`. Всё, снятое до привязки листинга, лежало с
  `record_id=NULL` и в выборку не попадало. На «Song Machine Season One» это
  давало «минимум за 3 мес — 4 990 ₽» при цене 3 352 ₽, державшейся третьи
  сутки, и «цена менялась слишком редко» там, где точек хватало с запасом.
  Фикс — привязка джойном через `store_listings.matched_record_id`: источник
  истины один и отставать не может. Побочно чинится перематч — история едет
  за листингом, а не остаётся у прежней записи.
  Тот же денорм фильтрует продюсер уведомлений о падении цены
  (`notification_tasks._run_price_drop`) — **вынесено отдельно**, там меняется
  количество пушей.
- **«Сейчас» в шторке порога считалось по оценке Discogs** — с карточки
  релиза приезжал `estimated_price_median_rub`, и предупреждение «порог выше
  текущей цены — сработает сразу» выносилось по числу, не имеющему отношения
  к реальным продажам: 5 322 ₽ у Discogs против 3 352 ₽, за которые пластинку
  в тот момент продавал магазин. Развели два понятия: `currentPrice` — живая
  цена маркета (показывается как «сейчас», решает предупреждение),
  `priceHint` — оценка Discogs, только для стартовых границ слайдера, наружу
  не выводится. Живую цену шторка берёт сама из
  `/records/by-id/{id}/offers/full` (работает и для discogs-записей, на
  неизвестный id отдаёт пустую сводку, а не 404). С радара `currentPrice`
  приходил корректно и раньше — там это `lowest_price_rub` из живых листингов.
- **Иконка радара в уведомлении не кликалась** — была обычным `<View>` внутри
  `TouchableOpacity` всей строки, своего обработчика не имела, поэтому тап
  отрабатывала строка и уводила в карточку релиза. Теперь на радар-уведомлениях
  иконка сама по себе кнопка: ведёт на `/radar` и помечает уведомление
  прочитанным.
- **Динамика цены свёрнута в раскрывающийся блок** — шапка несёт ответ
  («−18,6% за 3 мес»), график по тапу; развёрнут по умолчанию только при
  движении ≥5% на свежих данных. Дельту раньше не считал никто —
  `PriceSparkline` выводил first/current лишь чтобы выбрать цвет линии.

### Обложки

  psql'ем — как и описано в граблях шага 4.
