# Вертушка — 2026-08-17

## Итог дня
Главное — новый канал обложек: точный резолв по штрихкоду через Deezer
`/album/upc:<цифры>` вместо угадывания по имени. Дал ~113K обложек/сутки на
проде против ~16K у Yandex и ~2.9K у iTunes, почти без пересечения с
офлайн-каналами (MB→CAA к этому моменту исчерпаны). Плюс три прод-бага —
метрика покрытия молчала с 16 августа, финал ночного обхода магазина ложно
краснел на протухшем ORM-объекте, таймаут батча бэкфилла закрывал
неопрошенных мастеров навсегда — и логотип long-play в обеих витринах.

## Ключевые фиксы/решения

### Обложки
- **Канал по штрихкоду (Deezer UPC)** — угадывание по названию давало 24% на
  полном обходе 1.86М мастеров и промахивалось ровно на несовпадении строк
  (`Cause For Conflict` vs `Cause for Conflict (Remastered)`). У 3.6М релизов в
  дампе Discogs есть штрихкод, 2.59М из них без обложки. Замеры на проде:
  Deezer по UPC — 15.3% хит, 0.13с/запрос, обход за 3.5 дня; Yandex по имени —
  4.7%, 0.25с, 3.9 дня; iTunes по имени — 10.7%, 3.1с, 49 дней.
  Важные детали реализации: Deezer на превышение лимита отдаёт HTTP 200 с
  `{"error":{"code":4}}`, а не 429 — не ловится `raise_for_status`, отдельный
  тип `DeezerQuotaExceeded` прерывает прогон, чтобы не пометить `done` то, что
  не спросили; порог fanout — штрихкод с >20 релизами не берём (138 из 2.3М,
  худший держит 251 релиз — общий код лейбла); единица работы — уникальный
  штрихкод, не релиз.
- **Метрика покрытия не считалась с 16 августа** — `WHERE last_seen_at >=
  :d::date` ломает SQLAlchemy bindparam (`::` после `:d`), asyncpg падал с
  syntax error, джоба тихо валилась в APScheduler каждое утро в 6:15. Заодно
  выключены и алерты на регрессию тира. Фикс — `CAST(:d AS date)`, блок
  спроса обёрнут в try/except (докстринг обещал это поведение, код — нет),
  плюс guard-тест на класс ошибки по всему `app/`.
- **Таймаут батча бэкфилла закрывал неопрошенных мастеров навсегда** —
  `_gather_batch` на таймауте возвращал весь батч с `cover=None` для всех, а
  вызывающий код помечал всё как `done`. Для Deezer/Yandex спало (батч
  укладывался в таймаут), но для iTunes (3.1с/запрос) сработало бы каждый
  батч — ~60% из 1.33М мастеров ушли бы в `done` без единого запроса. Найдено
  при подготовке к включению iTunes-бэкфилла. Фикс: возвращать только реально
  опрошенные, размер батча — из `min_interval` провайдера (iTunes 200→61),
  пустой результат батча прерывает проход.

### Скрапер
- **Ложный красный на финале ночного обхода** — doctorhead записал 3358 из
  3359 позиций, но магазин пометился провалившимся. Цепочка: таймаут страницы
  → мёртвое соединение → упавший upsert → `db.rollback()` протух ORM-объект
  `store` → ленивая перечитка `store.id` → `MissingGreenlet`. Фикс от 08-12
  закрыл только цикл обхода; хвост остался в `_smoke_check`,
  `_mark_success`, `_mark_needs_browser` — все три переведены на скаляр
  `store_id` и UPDATE вместо мутации атрибутов.

### Магазины
- **Логотип long-play** подключён в обеих витринах (`STORE_REGISTRY` в
  мобилке — `require` там обязан быть статическим — и `_LOCAL_STORE_LOGOS` в
  вебе). Второе место легко пропустить: без slug в списке публичные страницы
  тихо рисуют монограмму вместо PNG. Добавлен тест, сверяющий белый список,
  папку веба и папку мобилки. `Design/Магазины/` — склад оригиналов всех
  девяти логотипов + README по требованиям.
