## Блок 0 — до деплоя. Иначе прод не поднимется

### 0.1 🔴 Секреты. Без этого API не стартует вообще

Я добавил гейт: вне `DEBUG=true` приложение отказывается запускаться с дефолтным или
коротким `JWT_SECRET_KEY` ([config.py](../../Backend/app/config.py) → `assert_secrets_ok`).
Это защита, но если на проде секрет короче 32 символов — **после деплоя API не поднимется**.

Проверить на сервере:

```bash
ssh deploy@85.198.85.12 'cd ~/vertushka/Вертушка/Backend && awk -F= "/^(JWT_)?SECRET_KEY=/{printf \"%s = %d символов\n\", \$1, length(\$2)}" .env'
```

Оба должны быть **≥ 32**. Если меньше — сгенерировать и вписать до деплоя:

```bash
openssl rand -hex 32
```

> Смена `JWT_SECRET_KEY` разлогинит всех: старые токены перестанут проверяться.
> Для приложения без публичного релиза это ничего не стоит, после релиза — уже событие.
> Если меняете, лучше сейчас.

### 0.2 🔴 nginx. Битый конфиг гасит весь сайт

`deploy.sh` пересоздаёт nginx **до** гейта `nginx -t`, поэтому ошибку в конфиге он поймает
уже после падения. Валидировать нужно заранее и отдельным контейнером — не `exec` в
работающий (после `git pull` там stale inode, проверите старый файл).

```bash
cd ~/vertushka/Вертушка/Backend && docker run --rm -v "$PWD/nginx/nginx.conf:/etc/nginx/nginx.conf:ro" -v "$PWD/nginx/active_upstream.conf:/etc/nginx/active_upstream.conf:ro" -v "$PWD/certbot/conf:/etc/letsencrypt:ro" nginx:alpine nginx -t
```

Ждём `test is successful`. Предупреждения про `listen ... http2` — старые, не от этих правок.

### 0.3 🔴 Блок `money` — не мой, но уронит вместе со всем

В [nginx.conf](../../Backend/nginx/nginx.conf) появился `server` для
`money.vinyl-vertushka.ru`. В комментарии внутри него написано, что до выпуска сертификата
блок обязан оставаться закомментированным — **а он не закомментирован**. nginx не стартует,
если не может прочитать любой `ssl_certificate`, и падает целиком: вместе с api и основным
доменом.

```bash
ssh deploy@85.198.85.12 'ls -la /etc/letsencrypt/live/money.vinyl-vertushka.ru/ 2>&1 | head -3'
```

Если каталога нет — либо выпустить сертификат, либо закомментировать блок. Проверка 0.2
это тоже поймает, но лучше знать причину заранее.

### 0.4 🟡 Служебный токен

`INTERNAL_API_TOKEN` не было ни в одном prod-примере env (дописал в
[.env.prod.example](../../Backend/.env.prod.example)). Без него `/health/detailed` и
`/health/covers` отдают 403 всем, включая вас.

```bash
ssh deploy@85.198.85.12 'grep -c "^INTERNAL_API_TOKEN=..*" ~/vertushka/Вертушка/Backend/.env || echo "НЕ ЗАДАН"'
```

Не блокер: `/health` для деплой-гейта работает без него.

## Блок 2 — после деплоя, за 5 минут

### 2.1 Заголовки безопасности

Главное, что чинилось в nginx: `add_header` в `location` отменяет унаследованные, и на
отдаче обложек заголовки пропадали.

```bash
curl -sI https://api.vinyl-vertushka.ru/covers/1.jpg | grep -iE "strict-transport|x-content-type"
```

Ждём **обе** строки. Раньше здесь был только `Cache-Control`.

```bash
curl -sI https://vinyl-vertushka.ru/ | grep -i "content-security-policy"
```

Ждём CSP с `base-uri 'self'` и `frame-ancestors 'none'`. И проверьте, что ушёл устаревший
заголовок — вывод должен быть пустым:

```bash
curl -sI https://vinyl-vertushka.ru/ | grep -i "x-xss-protection"
```

### 2.2 Health-ручки

```bash
curl -s https://api.vinyl-vertushka.ru/health
```

Ровно `{"status":"healthy"}` — без `db` и `redis`. Подробности теперь под токеном:

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://api.vinyl-vertushka.ru/health/detailed
```

Ждём `403`. С токеном:

```bash
curl -s -H "X-Internal-Token: ВАШ_ТОКЕН" https://api.vinyl-vertushka.ru/health/detailed
```

### 2.3 Rate limit

```bash
seq 1 30 | xargs -P 30 -I{} curl -s -o /dev/null -w "%{http_code}\n" -X POST https://api.vinyl-vertushka.ru/api/auth/login | sort | uniq -c
```

Ждём заметную долю `429`. Параллельность обязательна — последовательный curl не наберёт
2 r/s и лимит не сработает.

### 2.4 Удалённый эндпоинт

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X POST https://api.vinyl-vertushka.ru/api/records/ -H "Content-Type: application/json" -d '{"title":"x","artist":"y"}'
```

Ждём `404` или `405` — эндпоинт удалён. `401`/`422` означало бы, что он жив.

## Блок 3 — глазами пользователя, в приложении

Это то, куда автотесты не достают. Особенно после бампа FastAPI 0.109 → 0.115.

**Аутентификация** — самое рискованное место, там сменилась JWT-библиотека
(`python-jose` → `PyJWT`):

- [ ] вход по email и паролю
- [ ] **Apple Sign In** — путь через JWKS переписан целиком
- [ ] **Google Sign In** — то же самое
- [ ] сброс пароля: запросить код → ввести → задать новый → войти с новым
- [ ] после смены пароля старая сессия на втором устройстве разлогинилась

**Сброс пароля, отдельные проверки:**

- [ ] ввести неверный код трижды — текст ошибки **не меняется** и не сообщает, сколько
      попыток осталось
- [ ] пройти сброс до конца, затем повторить запрос с тем же `reset_token` — должен
      отвергнуться (одноразовость)
- [ ] пароль из 40 русских букв при регистрации — понятная ошибка про длину, не молчаливое
      принятие

**Загрузка фото:**

- [ ] добавить фото к пластинке
- [ ] большое фото с телефона (12 Мп) проходит

**Блокировка** — поведение расширилось, проверьте с двух аккаунтов:

- [ ] заблокировать пользователя → он **исчезает из подписчиков** (раньше оставался)
- [ ] заблокированный не может подписаться
- [ ] от него не приходят пуши

**Маркет и обложки** — тут был SSRF-гард, он мог задеть легальные источники:

- [ ] обложки грузятся в поиске, в коллекции и в Маркете
- [ ] `docker compose logs api-blue | grep "отказ качать"` — пусто. Если есть строки,
      значит гард отбивает нормальный CDN и туда надо посмотреть

## Блок 4 — публичный профиль и XSS

Главный блокер. Проверяется руками за минуту.

1. Создайте пластинку, в поле **исполнитель** вставьте: `<svg onload=alert(1)>`
2. Добавьте вторую с тем же исполнителем (нужно ≥2, чтобы он стал «топ-артистом»)
3. Включите публичный профиль и откройте `https://vinyl-vertushka.ru/@ваш_логин`

Ждём: строка видна как **текст**, алерта нет. В исходнике страницы — `&lt;svg`, а не `<svg`.

4. Удалите тестовые пластинки

## Блок 5 — то, что проверяется не в коде

### 5.1 Условия OpenAI

В политику добавлена фраза, что кадр «не сохраняется ни у нас, ни в качестве обучающих
данных» ([privacy.html](../../Backend/app/web/templates/privacy.html), раздел 3).
Сверьте со своим тарифом OpenAI — если для него это не так, формулировку надо поправить,
иначе политика опять разойдётся с реальностью.

Заодно в App Store Connect: **Photos or Videos** должны быть помечены как передаваемые
третьей стороне.

### 5.2 Браузерные парсеры, похоже, не работают

`Dockerfile` не выполняет `playwright install` — бинарников Chromium в образе нет, а джобы
`weekly_full_crawl_browser` и `daily_incremental_crawl_browser` стоят в расписании. Из кода
не подтвердить, нужны логи:

```bash
ssh deploy@85.198.85.12 'cd ~/vertushka/Вертушка/Backend && docker compose -f docker-compose.prod.yml logs scheduler --since 168h | grep -iE "browser|playwright|Executable" | tail -20'
```

Если там ошибки запуска браузера — либо ставить его в образ, либо снимать джобы с
расписания. Это не безопасность, просто тихо не работает.

### 5.3 Вычистка удалённых аккаунтов

Джоба `purge_deleted_users` теперь в планировщике (04:30). Убедиться, что она реально
отработала — через сутки после деплоя:

```bash
ssh deploy@85.198.85.12 'cd ~/vertushka/Вертушка/Backend && docker compose -f docker-compose.prod.yml logs scheduler --since 24h | grep purge_deleted_users'
```

Ждём строку `purge_deleted_users: нечего вычищать` или отчёт об удалении. **Тишина
означает, что джоба снова не запускается** — именно это и было исходной проблемой.

## Что осталось незакрытым

Не пропало, а сознательно отложено — чтобы вы знали, чего не ждать:

| Что | Почему отложено |
|---|---|
| Токен WS в `error_log` | Формат настраивается только у `access_log`; нужна ticket-схема |
| CSP с `'unsafe-inline'` | Снятие требует переписать 14 инлайновых обработчиков в шаблонах |
| `--workers 1` | Не уязвимость, а потолок. Переход требует Redis-лимитов |
| Обложки user-записей при удалении аккаунта | Продуктовое решение: запись переживает автора |
