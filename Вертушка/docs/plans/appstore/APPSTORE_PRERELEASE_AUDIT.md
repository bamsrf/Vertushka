**Новое, чего в аудите нет вовсе** (правила поменялись после его написания):

1. **Отзыв Apple-токена при удалении аккаунта** — требование с 30.06.2022, в
   аудите пропущено. Реализовано 2026-08-18 (`Backend/app/services/apple_auth.py`),
   но **включается только с ключом .p8 в окружении** — см. Submission Kit §8.
2. **Шкала 12+ отменена**: теперь 4+/9+/13+/16+/18+, обновлённая анкета
   обязательна с 31.01.2026. Везде, где в этом файле написано «12+», читать
   Submission Kit §5.
3. **Декларация social media capability** — вопросы добавлены 09.07.2026,
   обязательны при сабмите **с сентября 2026**. Вертушка попадает под
   определение (профили, подписки, лента, DM).
4. **Trader status (DSA)** — обязателен для всех аккаунтов; при доступности в ЕС
   контакты публикуются, без верификации приложение снимается со всех 27
   сторфронтов. Публикуемся через бразильский аккаунт — Submission Kit §7.
5. **Минимальный SDK: Xcode 26 / iOS 26 SDK, обязателен с 28.04.2026** — дедлайн
   уже прошёл. `eas.json` образ билда не пинит, значит зависим от дефолта EAS.
   Проверяется одним прод-билдом с аплоудом; отобьётся на приёме бинаря.

**Мелочи, закрытые тем же заходом:** английская заглушка `NSFaceIDUsageDescription`
(биометрия не используется — плагин `expo-secure-store` отключён от неё),
Google Sign-In исключён из сборки, in-app политика догнала веб-версию по OpenAI,
в Terms появился минимальный возраст.

**Осталось операционное, кодом не закрывается:** демо-аккаунт, скриншоты,
иконка/маскот (M1), заполнение полей ASO-кита, TestFlight-soak.

## Резюме

Техническая база в хорошем состоянии: Apple Sign In есть, in-app удаление аккаунта есть,
privacy/terms живут по URL (оба отвечают 200), Sentry/GlitchTip активен, `ITSAppUsesNonExemptEncryption=false`,
privacy manifest (accessed API types) заполнен, ATT не нужен (Amplitude выключен, GlitchTip self-hosted).

**Но при сабмите сегодня — реджект практически гарантирован** по Guideline **1.2 (UGC)** и
высоковероятен по **2.1 (demo-аккаунт)** и **4.0/2.4.1 (iPad)**. Ниже — все пробелы по
убыванию критичности и план закрытия.

## Блок A — Реджект-блокеры (без этого не сабмитить)

### A1. Guideline 1.2 — UGC moderation ⛔ главный блокер

**Факт:** UGC в апке = user-records, публичные профили, DM. Есть только block в чате
(`messages/[conversationId].tsx` → `blockUser`). Нет: report-кнопок, report-эндпоинта,
zero-tolerance EULA, чекбокса принятия условий при регистрации, takedown-гейта на
`rejected`-записи, login-гейта по `is_active`.

**Что делать:** выполнить целиком существующий план [UGC_MODERATION_M2.md](UGC_MODERATION_M2.md).
Он корректен и полон. Ключевые пункты:
1. Backend: модель `Report` + миграция + `api/reports.py` (`POST /reports/` с rate-limit,
   `POST /reports/{id}/action` для staff, `GET /reports/` для staff).
2. Backend-гейты: `get_record` → 404 чужим для `moderation_status='rejected'`;
   `auth.py` login → 403 при `is_active=False`.
3. Mobile: report-кнопка в 3 точках (карточка чужого user-record, чужой профиль, чат) +
   `lib/api.ts::reportContent`.
4. Mobile: экраны `app/legal/terms.tsx` + `app/legal/privacy.tsx` (или WebView на живые URL),
   чекбокс «принимаю условия» в `register.tsx`, ссылки в `profile.tsx` → Настройки.
5. Текст Terms дополнить: zero-tolerance формулировка + контакт для жалоб (email).
   Тот же контакт — в App Store Connect metadata.

**Оценка:** 2–3 дня. **Приоритет: №1.**

### A2. Guideline 2.1 (App Completeness) — demo-аккаунт и review notes

**Факт:** апка требует логин с первого экрана. Без работающего демо-аккаунта в review notes —
автоматический реджект «we were unable to sign in».

**Что делать:**
- Создать стабильный демо-аккаунт (email+пароль, НЕ Sign in with Apple) с наполненной
  коллекцией: 15–20 записей, пара ачивок, вишлист, активный публичный профиль.
- Review notes (можно EN, лучше EN+RU): кто мы, что делает апка, сценарий на 5 шагов
  (логин → коллекция → скан штрихкода → карточка записи → публичный профиль),
  явно указать источники данных (см. A5) и наличие report/block-механизмов (после A1).
- Демо-аккаунт исключить из всех фоновых чисток/soft-delete джобов.

**Оценка:** 0.5 дня. Notes писать после A1, чтобы упомянуть модерацию.

### A3. iPad — Guideline 4.0 / 2.4.1

**Факт:** `app.json` → `"supportsTablet": true`, но iPad-раскладка ни разу не тестировалась
(в доках/планах ни одного упоминания iPad-тестов). Ревьюеры Apple тестируют на iPad —
если гриды/модалки/камера-сканер разваливаются, это реджект.

**Что делать (выбрать одно):**
- **Вариант 1 (рекомендую для v1.0):** `"supportsTablet": false` — апка ставится на iPad
  в iPhone-режиме letterbox, претензий у ревью нет. Одна строка, ноль риска.
- Вариант 2: полный прогон на iPad-симуляторе (11" и 13"), фикс разъехавшихся экранов.
  Это дни работы — не для первого релиза.

**Оценка:** 5 минут (вариант 1). **Решить до production-билда.**

### A4. App Store Connect — метаданные не заполнены

**Факт:** запись в ASC есть (`ascAppId: 6774999020`, `appleTeamId` заполнен), но нет:
описания, keywords, скриншотов, age rating, App Privacy questionnaire, support URL.

**Что делать:**
1. **App Privacy (questionnaire):** декларировать честно —
   - Contact Info: Email (linked to identity, для функционирования аккаунта);
   - User Content: Photos (аватары/обложки), Other UGC (записи, сообщения);
   - Identifiers: User ID;
   - Diagnostics: Crash Data (Sentry/GlitchTip, linked — если шлём user context; проверить
     `Sentry.setUser` в коде и либо декларировать linked, либо слать без user id);
   - **Tracking: НЕТ** (Amplitude выключен, GlitchTip свой) → ATT-промпт не нужен.
2. **Age Rating questionnaire:** с UGC + чатом и работающей модерацией (A1) честные ответы
   дают 12+ (Infrequent/Mild UGC). Без A1 пришлось бы ставить 17+ — ещё одна причина
   сделать A1 первым.
3. Описание RU (primary locale ru) + EN (доп. локаль листинга — опционально, но дёшево).
4. Keywords: винил, пластинки, коллекция, discogs, vinyl, records, барахолка и т.п. (100 симв.).
5. Support URL: страница на vinyl-vertushka.ru с контактом (можно /support с mailto).
6. Privacy Policy URL: уже есть (https://vinyl-vertushka.ru/privacy, отвечает 200) ✅.

**Оценка:** 0.5–1 день (без скриншотов — они в A6).

### A5. Guideline 5.2.2 / 5.2.3 — права на данные (Discogs dump + scraped магазины)

**Факт:** апка публично показывает данные из локального Discogs-дампа, обложки (Discogs/CAA)
и scraped-цены магазинов («Купить сейчас», `OffersBlock`). В ROADMAP это уже помечено
как legal-риск. Для Apple это Guideline 5.2.2: «apps that display third-party content
must have the rights».

**Что делать (минимум для v1.0):**
1. Прочитать Discogs API ToS в части дампов/редистрибуции; monthly data dumps у Discogs
   публичны под CC0 (metadata) — но **проверить актуальную лицензию** и зафиксировать
   вывод в этом файле.
2. Добавить атрибуцию: строка «Данные о релизах — Discogs» на карточке записи или в
   разделе «О приложении» (Discogs это требует при использовании их данных/API).
3. Обложки: указать источник (Discogs / Cover Art Archive) там же.
4. Магазины в «Купить»: ссылки наружу (Linking) — это ок для физических товаров
   (3.1.5(a), IAP не нужен). В review notes прямо написать: «покупка винила происходит
   на сайтах магазинов, апка — каталог/агрегатор».
5. В review notes: краткий абзац об источниках данных, чтобы ревьюер не задавал вопрос.

**Оценка:** 0.5 дня (проверка ToS + атрибуция). Полный legal-аудит скрейпинга — отдельно, не блокер сабмита.

### A6. Скриншоты + иконка (зависимость от M1)

**Факт:** M1 (маскот, иконка v2) — Not started. Текущий `icon.png` — плейсхолдер-уровень.
Без скриншотов сабмит невозможен физически.

**Что делать:**
- Требуемые размеры: iPhone 6.9" (1320×2868) — с 2024 обязателен только один размер
  (6.9" или 6.5"), остальные скейлятся. 5–8 штук.
- Если M1 затягивается: сделать «честные» скриншоты текущего UI без маскота + простую
  иконку — это НЕ реджект-риск, чисто маркетинг. Не блокировать релиз маскотом,
  если он не готов (решение за owner'ом, но ревью пропустит и без маскота).
- Иконка обязана пройти HIG: без прозрачности, без скруглённых углов в файле.

**Оценка:** 1 день (скриншоты по готовому UI) / зависит от иллюстратора (маскот).

## Блок B — Высокий риск / гигиена (сделать до сабмита, дешёво)

### B1. In-app ссылки на Privacy/Terms — Guideline 5.1.1(i)

Для account-based апок Apple хочет privacy policy доступной **внутри** приложения, не только
в метаданных. Сейчас в `profile.tsx` ссылок нет (grep пуст). Закрывается пунктом A1.4
(экраны legal + строки в настройках). Отдельно отмечено, чтобы не потерять, если A1 порежут.

### B2. Android `RECORD_AUDIO` — лишний пермишен

`app.json` → android.permissions содержит `RECORD_AUDIO`, но в коде аудио-фич нет (grep пуст).
На Play это гарантированный вопрос в data safety; на iOS не влияет, но правим в том же PR:
удалить `RECORD_AUDIO` из permissions.
**Оценка:** 5 минут.

### B3. Push-permission — холодный промпт при старте

`_layout.tsx:186` — `requestPermissionsAsync` сразу после логина без контекста. Не реджект,
но: (а) низкий opt-in, (б) ревьюеру виден промпт «из ниоткуда» сразу после входа.
**Что делать:** перенести запрос на первое осмысленное событие (первое сообщение / подписка /
экран настроек уведомлений) или показать pre-permission объяснялку. Если некогда — оставить,
риск реджекта ~нулевой.
**Оценка:** 0.5 дня (или пропустить).

### B4. Privacy manifest — collected data types

`NSPrivacyAccessedAPITypes` заполнен ✅, но `NSPrivacyCollectedDataTypes` отсутствует.
Для собственного кода это мягкое требование (жёсткое — questionnaire в ASC), но добавить
дёшево и убирает расхождение манифеста с декларацией: email, user content, user ID,
crash data — те же ответы, что в A4.1.
**Оценка:** 30 минут.

### B5. Sentry user context vs App Privacy

Проверить, вызывается ли `Sentry.setUser(...)` с email/id. Если да — в A4.1 Diagnostics
декларировать «linked to identity», либо убрать user из событий. Несовпадение декларации
и трафика — то, за что Apple начала цепляться в 2025+.
**Оценка:** 30 минут.

### B6. Пройти флоу восстановления аккаунта глазами ревьюера

Удаление аккаунта — soft delete с окном восстановления (`auth.py:422`). Apple разрешает
grace period, **если юзеру это ясно сказано**. Проверить: диалог «Удалить аккаунт?» в
`profile.tsx:673` должен явно писать срок окна восстановления и что данные будут удалены
после. Если текста нет — добавить одну строку.
**Оценка:** 30 минут.

## Блок C — Не блокеры, но заметит ревью/юзеры первой недели

- **C1. Крэш-фри soak:** по плану M2 — ≥2 недели TestFlight, crash-free ≥99%. Не сокращать:
  реджекты за крэш при запуске (2.1) — самая частая причина отказа.
- **C2. Пустые состояния для demo/нового юзера:** ревьюер может создать свежий аккаунт —
  все empty states должны быть осмысленными, не спиннеры навсегда. Прогнать регистрацию
  на чистом аккаунте (включая verify-code флоу — работает ли доставка кода на ревью-емейлы?
  Если код по email, у ревьюера может не быть доступа → демо-аккаунт из A2 обязателен).
- **C3. Локаль листинга EN:** RU-only листинг легален, но EN-описание расширяет аудиторию
  бесплатно. После релиза — ок.
- **C4. `userInterfaceStyle: light`** — форс светлой темы легален, тёмная тема не требуется.
- **C5. Deep links / universal links** — scheme `vertushka` есть; associated domains для
  https-ссылок публичных профилей — пост-релиз.
