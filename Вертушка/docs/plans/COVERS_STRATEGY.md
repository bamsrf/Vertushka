> [COVERS_RATE_LIMIT_STRATEGY.md](COVERS_RATE_LIMIT_STRATEGY.md) (каналы),
> [MB_DELTA_REFRESH.md](MB_DELTA_REFRESH.md) (месячный рефреш дампов),

## Система координат: три слоя, которые нельзя смешивать

1. **URL-слой** — строки `cover_image_url` в Postgres (2.3 млн). Байты. Это
   «знание, где лежит обложка», а не сама обложка. Копится каналами, бэкапится
   CSV-срезом (`~/backups/covers_urls_YYYYMMDD.csv.gz`).
2. **Файловый слой** — зеркало `uploads/covers/` (сейчас LRU-кэш 8 ГБ на VPS).
   Качается **по спросу** (просмотр, Маркет-конвейер), не превентивно.
3. **Раздача** — nginx-статика + imgproxy. Пока не болит.

Вопрос «куда складывать все обложки» — это вопрос про слой 2, и ответ на него:
**«все» складывать не надо**. База 13.4 млн изданий, живой спрос покрывает
доли процента. Складывается только просмотренное/рыночное — навсегда.

## Где мы сейчас (замерено 27.08.2026)

- URL-слой: **2.30 млн** обложек (69% — бесплатный CAA; ~600 тыс. — заработаны
  Discogs-каналами, при потере невоспроизводимы быстро → CSV-бэкап).
- **Маркет покрыт на 99.97%** (35 793 из 35 805 in-stock позиций).
- Живой холодный спрос при DAU 1–3: единицы–десятки обложек в день,
  live_miss — единицы В НЕДЕЛЮ. Проблемы покрытия для текущих юзеров **нет**.
- Мелкие мастера: 13.3% (было 54% в августе) — ночной перегрев дожёвывает.
- Зеркало: 5.4 ГБ → плато 8 ГБ (LRU-кап) через 2–3 дня, дальше не растёт.
- Диск VPS: свободно 8.1 ГБ, на плато обложек будет ~5.5 ГБ.

## Принципы (что НЕ делаем)

- **Не качаем базу целиком.** 13.4 млн × 250 КБ ≈ 3+ ТБ и годы квот ради
  хвоста, который никто не откроет. Полнота меряется по спросу
  (`/health/covers` → `demand`, `market_in_stock`), не по проценту от базы.
- **Не обходим rate limit Discogs** мульти-ключами (ToS). Кэшировать сами
  картинки — можно (подтверждено модератором форума), URL-метаданные — нет.
- **Не строим CDN и не выносим раздачу**, пока nginx не болит (см. триггеры
  в milestone-доке).
- **Не покупаем сторонние «библиотеки обложек»** — легальных оптовых
  источников, кроме CAA, не существует; всё остальное — те же API с квотами.

## Куда складывать: ответ про облако

**Да, объектное хранилище (S3) делать стоит — но по триггеру, не сегодня.**

Почему да (стратегически):
- LRU-кэш **выбрасывает данные**: при росте DAU выброшенное перекачивается,
  сжигая квоту Discogs и латентность CAA (archive.org из РФ — секунды).
- Диск VPS — стена: 8 ГБ потолок ≈ 85 тыс. файлов. S3 снимает потолок навсегда.
- Зеркало сейчас **не бэкапится вообще**; S3 с версионированием закрывает и это.

Почему не сегодня (по цифрам):
- DAU 1–3, cold-спрос единицы/день → LRU-эвикция ничего не перекачивает.
- Маркет покрыт, промахи единичны. Ни один триггер milestone-плана не сработал
  (ближайший к срабатыванию — «диск < 5 ГБ стабильно»: на плато будет ~5.5).

Параметры решения, когда время придёт (см. execution в
[COVERS_S3_IMGPROXY_MILESTONE.md](COVERS_S3_IMGPROXY_MILESTONE.md)):
- **Провайдер**: любой S3-совместимый в РФ. Дефолт-рекомендация — Selectel
  Object Storage или Yandex Object Storage (1–2 ₽/ГБ/мес, S3 API, imgproxy
  умеет читать S3 нативно). Выбор = 15 минут, вкус владельца.
- **Объём и цена**: стартовая миграция ~8 ГБ ≈ 10–20 ₽/мес; годовой горизонт
  30–80 ГБ ≈ 50–160 ₽/мес. Даже гипотетические «все 2.3 млн URL скачаны»
  (~575 ГБ) ≈ 600–1200 ₽/мес — цена не является фактором решения вообще.
- **Схема**: S3 = вечное хранилище (ничего не удаляем), VPS-диск остаётся
  горячим кэшем раздачи; LRU превращается из «потери данных» в «выселение
  в холодный слой».

## Дорожная карта

### Этап 0 — до сабмита в App Store (сейчас)
Руками не делать ничего: drip капает (~30K/день), конвейер Маркета зеркалит,
перегрев дожёвывает мелкие мастера. Единственное обязательное действие —
**снять COVER_DRIP_-профиль перед сабмитом** (пункты уже в PLAN_RELEASE_v2 и
APPSTORE_PRERELEASE_AUDIT).

### Этап 1 — сразу после сабмита (низкая цена, большой эффект)
- **MusicKit-ключ** (действие владельца, ~15 мин в dev-аккаунте, Team
  G47JLHB869) → подключается канал #5.
- Ежемесячный MB/CAA-рефреш — первый: конец сентября.
- (Опционально, отдельная задача) непрерывный drip-воркер вместо минутных
  тиков — ×2 к темпу канала #3 без роста квоты.

### Этап 2 — S3 (по любому из триггеров milestone-дока)
Триггеры дословно там; практически ближайшие два: «выход в стор с
маркетинговым пушем» и «диск стабильно < 5 ГБ». Тогда: выбрать провайдера →
трек A milestone-плана (S3 + imgproxy). Одновременно поднять VPS до 4 ГБ RAM
(предусловие плана).

### Этап 3 — рост (DAU сотни+)
CDN перед nginx, вынос раздачи; месячный delta-ингест Discogs-дампа
(новые релизы в индекс → каналы 1–3 их подхватывают автоматически).

## Метрики, по которым живёт стратегия

Всё уже собирается, смотреть `/health/covers` (X-Internal-Token):
- `market_in_stock.pct` — покрытие Маркета (норма ≥ 99%);
- `demand.cold_per_dau` и `cold_outcomes.live_miss` — реальный голод юзеров;
- `master_tier.low_res_pct` — качество (норма: падает к ~5%);
- `cover_sources.free_pct` — доля бесплатных источников (норма: растёт);
- диск: алёрт disk guard + плато 8 ГБ.

Ревизия документа — при срабатывании любого триггера этапа 2 или после
первого месяца в сторе.
