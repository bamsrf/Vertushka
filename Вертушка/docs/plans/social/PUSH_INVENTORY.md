## Через что проходит каждый push

Порядок жёсткий, провалился любой шаг — push не уходит, запись в ленте «Ты»
всё равно остаётся.

1. **Флаг `notify_*`** — маппинг типа на тумблер в `PUSH_PREFERENCE_FIELD` (`services/push.py`).
   Типа нет в маппинге → выключить нельзя.
2. **Тихие часы** — сравнение в UTC, окно через полночь поддержано. По умолчанию выключены.
3. **Частотный кап** — 1 push на тип в час через Redis. У вишлиста слот на пластинку,
   у ачивок — на код ачивки. Чат кап минует (`bypass_cap`).
4. **Живой Expo-токен** — мёртвые зачищаются по receipt-ам, джоб каждые 20 минут.

## Подарки

Push дублируется письмом; гость без аккаунта получает только письмо.

| Тип | Что приходит | Когда | Тумблер | Статус |
|---|---|---|---|---|
| `gift_booked` (анонимно) | **Кто-то забронировал подарок**<br>«Nirvana — Nevermind» из твоего вишлиста | Бронь подарка из вишлиста | Подарок забронирован | Включён, режим по умолчанию |
| `gift_booked` (даритель раскрыт) | **Влад дарит тебе пластинку**<br>«Nirvana — Nevermind» | То же, если владелец включил `reveal_gifter_to_owner` | Подарок забронирован | Включён |
| `gift_confirmed` | **Подарок на месте**<br>Ксения добавляет «Nevermind» в коллекцию | Получатель добавил пластинку в коллекцию | Подарок получен | Включён |
| `gift_rejected` | **Бронь подарка снята**<br>«Nevermind» снова свободна для брони | Владелец отменил бронь | **нет** | Типа нет ни в `NOTIFICATION_TYPES`, ни в `PUSH_PREFERENCE_FIELD`; текст захардкожен в `api/gifts.py` мимо `push_copy` |

## Сообщения

Единственная группа, где текст собирается на месте: title — имя отправителя,
body — превью сообщения до 120 символов.

| Тип | Что приходит | Когда | Тумблер | Статус |
|---|---|---|---|---|
| `message` | **Ксения**<br>Нашла тот самый японский прессинг, скинуть ссылку? | Каждое входящее в принятом диалоге | Новое сообщение | Часовой кап обойдён (`bypass_cap`) — каждое сообщение даёт свой push. Записи в ленту «Ты» не создаёт. Дополнительно глушится мьютом диалога |
| `message_request` | **Ксения**<br>Привет! Видел твою коллекцию Blue Note… | Первое сообщение от постороннего | Новое сообщение | Кап 1/час на весь тип; повторные бампают одну нить в ленте. Мьют треда глушит push, запись в «Запросах» остаётся |

## Что пользователь видит в настройках

Экран «Уведомления» → 6 групп, 10 переключателей.

| Группа | Переключатель | Поле | По умолчанию | Что реально гасит |
|---|---|---|---|---|
| Социальные | Новый подписчик | `notify_new_follower` | вкл | `new_follower` + «заявка принята» |
| Социальные | Запрос на подписку | `notify_follow_request` | вкл | `follow_request` |
| Сообщения | Новое сообщение | `notify_messages` | вкл | `message` + `message_request` |
| Подарки | Подарок забронирован | `notify_gift_booked` | вкл | `gift_booked` |
| Подарки | Подарок получен | `notify_gift_confirmed` | вкл | `gift_confirmed` |
| Вишлист | Снова в продаже | `notify_wishlist_in_stock` | вкл | все 4 типа вишлиста, включая дайджест |
| Достижения | Новая ачивка | `notify_achievement` | вкл | `achievement_unlocked` + `level_up` |
| Достижения | Вехи | `notify_milestone` | вкл | `milestone_unlocked` |
| Не беспокоить | Тихий режим + начало/конец | `quiet_hours_*` | выкл | все push; время хранится в UTC, экран показывает локальное |
| Системное | Обновления приложения | `notify_app_updates` | вкл | **ничего** — отправителя такого типа в коде нет |

Разрешение на уведомления сознательно не запрашивается на холодном старте —
только из «Сообщений» и с экрана настроек (`Mobile/lib/push.ts`). Для App Review
это плюс, но и причина, по которой у части пользователей токена не будет вовсе.

## Письма

Resend как основной канал, SMTP — запасной (`services/notifications.py`,
`services/email.py`). Тон тот же, что в пушах: на «ты».

| Тема | Кому | Повод |
|---|---|---|
| Кто-то хочет подарить тебе пластинку / «{Имя} дарит тебе пластинку» | владелец вишлиста | бронь подарка |
| Бронь подтверждена — Вертушка 🎵 | даритель | бронь создана, 60 дней, ссылка на отмену |
| Подтвердите бронь — Вертушка 🎵 | даритель | только при включённой проверке email |
| Твой подарок получен | даритель | получатель добавил пластинку в коллекцию |
| Бронь подарка снята | владелец / даритель | отмена с любой стороны |
| Бронь подарка истекла | даритель | авто-освобождение по сроку |
| Подарок больше не нужен | даритель | пункт удалён из вишлиста |
| Бронь подарка истекает через неделю | даритель | ежедневный джоб в 10:00 |
| Вертушка — код для сброса пароля | любой | восстановление доступа |

Тумблеров у писем нет: все девять транзакционные, привязаны к действию самого
пользователя или к его подарку.

## Расхождения, которые видны в срезе

Не блокеры сабмита, но на вопрос «можно ли это выключить» сейчас отвечать нечем.

### 1. Тумблер «Обновления приложения» ничего не выключает

Флаг сохраняется и возвращается API, но ни один push не отправляется с типом,
который на него завязан. Пользователь видит переключатель, за которым пусто.
Либо убрать с экрана, либо завести канал продуктовых рассылок.

`Mobile/app/settings/notifications.tsx` (группа «Системное») · `Backend/app/schemas/user.py:113`

### 2. Тип `gift_rejected` живёт мимо реестра

Его нет в `NOTIFICATION_TYPES` и в маппинге тумблеров, текст написан прямо в
хендлере. Push уходит всегда — тумблер «Подарок забронирован» его не гасит.

`Backend/app/api/gifts.py` (отмена брони) · `Backend/app/models/notification.py`

### 3. Дайджест приходит в 13:00 по Москве

Расписание задано как «понедельник 10:00», а планировщик считает в UTC.
Если задумано было утро — сдвиг на три часа.

`Backend/app/main.py`: `weekly_wishlist_digest`
