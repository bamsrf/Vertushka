### ⚠️ Единственная точка для ручной проверки
**APNs-ключ (push credential) для iOS живёт в EAS, не в репозитории.** Без загруженного APNs key Expo выдаёт токены, но iOS-доставка молча падает.
Проверить: `eas credentials` → iOS → Push Notifications Key. Должен быть `.p8` key привязан к `com.vertushka.app`.

## 4. Рекомендованный порядок работ

**Базовая полнота (закрыть дыры):**
1. **Подтвердить APNs key в EAS** — иначе всё ниже на iOS не доставляется. Блокер №1.
2. **A4 — push на сообщения.** `send_push` в `messages.py` рядом с `push_event`, гейт `notify_messages`, тип `message`. Freq-cap осмыслить: не на каждое сообщение в активном диалоге — лучше «N новых от {X}».
3. **C3 price_drop** — добить триггер, маппинг в `push.py` уже готов.

**Прямое взаимодействие (юзера касается лично):**
4. **G4 — реакция на сообщение.** WS-событие `message.reaction` уже есть, добавить push-ветку.
5. **G3 — друг хочет пластинку (идея для подарка).** Ведёт в gifts → монетизация. Источник `wishlist_add` в ленте готов.
6. **B3 — напоминание дарителю об истекающей брони.** Рядом с `auto_release_expired_bookings` в scheduler.

**Вторая волна:**
7. **F1 app_updates** — админ-broadcast через `send_pushes_batch`.
8. **E1 / F2 / F4** — рост ценности коллекции, win-back, manual-match. После базовой полноты.

## 5. Принцип отбора (почему часть идей отброшена)
Push оправдан, когда событие: (а) **про человека или дефицит** (друг, подарок, «снова в продаже»), либо (б) **редкое и значимое**. Отбраковано:
- **D2 майлстоуны** — дубль ачивок.
- **E2/E3** — оценка/курс меняются ежедневно → шум, не сигнал.
- **F3 онбординг** — юзер уже в приложении.
- **D4 стрики** — не Duolingo, чужая механика для каталога винила.
- **G1/G2 активность друзей** — чужая кухня: то, что друг добавил пластинку или ачивку, юзера напрямую не касается.
- **H1 новинки** — обновляются слишком редко, чтобы держать отдельный канал.
- **H2/H3 просмотры профиля и витрина** — не делаем.

## 6. iOS: что сделать, чтобы пуши не падали

Канал для iOS: устройство → APNs-токен → Expo (`getExpoPushTokenAsync`) → наш бэк → Expo Push API → APNs → устройство. Падает обычно в двух местах: **APNs-ключ в Expo** (внешнее) и **отсутствие проверки доставки** (код). Что в репо есть: `expo-notifications ~0.32.17`, plugin в `app.json`, Apple привязан в `eas.json` (`appleTeamId G47JLHB869`, `ascAppId 6774999020`), store-distribution билды.

### 6.1. Внешнее — проверить руками (вне репо, частые причины тихого фейла)
| # | Что | Как проверить / сделать |
|---|---|---|
| I1 | **APNs Key (.p8) загружен в EAS** — критичнее всего | ✅ **РЕШЕНО 2026-06-06: ключ `XQ7426JXM3` (team `G47JLHB869`) залит в EAS и привязан к `com.vertushka.app`** (`pushKey` теперь не-null, `updatedAt 2026-06-06T05:47Z`). Залито через EAS GraphQL (`createApplePushKey` + `setPushKey`). `.p8` лежит локально в `docs/Notifications/` (в `.gitignore`, в git не попадает). |
| I2 | **Push capability на App ID** | Apple Developer → Identifiers → `com.vertushka.app` → Push Notifications = enabled. EAS-билд включает автоматически, но проверить стоит. |
| I3 | **`aps-environment` entitlement в билде** | Только EAS-билд (`preview`/`production`), не Expo Go. В Expo Go iOS-пуши не работают вообще. Проверить: установить TestFlight-сборку, не Go. |
| I4 | **Токен реально долетает до БД** | После установки на физическом устройстве (не симулятор) → `User.push_token` не NULL. Если NULL — проблема на этапе permission/регистрации. |
| I5 | **Тест-отправка** | `curl exp.host/--/api/v2/push/send` с токеном устройства, либо expo.dev/notifications. Ответ `ok` + пуш пришёл = канал жив. |
